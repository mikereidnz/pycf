# pycf Audit Report (v0.1.0.dev0+0d72ce0)

Companion to `plan/audit_2026-04-27_171732_plan.md`.
Run date: 2026-04-27 (local).
Mode: Unattended audit per §5; build/test artifact changes allowed; no source files modified.

## 1. Executive Summary

Overall health: **good**. Builds cleanly, all C and Python tests pass, sanitizer
run clean, coverage 67% overall and 95%+ on the highest-risk numerical
modules. No critical (release-blocking) findings.

Highest-risk active issue: **brittle/inconsistent linting & pre-commit
configuration**. Running `pre-commit run --all-files` silently rewrites 182
files (formatting hooks plus generated docs HTML), which contradicts the
audit policy of "do not modify source files" and is dangerous for users who
run `pre-commit install`. The `bandit` and `semgrep` pre-commit hooks are
broken (config errors and missing `pbr`/`semgrep-core`).

Release-readiness: yes for internal/scientific use; no behavioural regressions
observed vs. legacy. Recommended cleanup before broader release: see §6.

## 6. Suggested Remediation Order

Rationale: fix the things that mislead future contributors first, then
silence noise, then tackle code-quality items.

1. **F-007 / F-005 / F-006** — repair pre-commit + bandit + semgrep
   configurations (or remove them). Today they break on first run and rewrite
   files. This is the single highest-impact cleanup.
2. **F-015 / F-012** — stop tracking `docs/_build/`; add `.gitignore` entry;
   add a `[docs]` extra and document `sphinx-build` flow. Removes most of
   pre-commit's noise.
3. **F-008** — move `_cfl_error_handler` definition out of the header (one
   TU owns it; others extern-declare it). This is a correctness bug for any
   user relying on `pycf.cfl.set_error_handler` to capture all C-side errors.
4. **F-001** — make `_cfl_default_error_handler` and friends `extern inline`
   or non-static so they can be referenced by `inline` (non-static) functions
   without warnings. Often resolved automatically by F-008.
5. **F-002 / F-011** — triage `pyemp.py`: decide which `Spectrum.*` attrs
   are intended public API (then add them and tests) and which are dead
   refactor remnants (then delete). Until decided, mark `pyemp` as
   experimental in docs.
6. **F-003 / F-014** — flake8 cleanup: rename ambiguous `I`, fix two long
   lines, drop trailing newline in generated `__version__.py`.
7. **F-009 / F-010** — small Cython hygiene fixes.
8. **F-013** — add `make -C cfl asan` target.
9. **F-004** — replace `shell=True` with an argv list and remove the
   inline f-string interpolation in `pyemp.py`.

## 8. Test Coverage Deep Dive (post-CI hardening)

Follow-up review focused on a single question: **are the user-facing
Python and Cython functions in `pycf/` actually probed for correctness,
or do tests merely confirm "it didn't crash"?**  Method:

1. Enumerate the `def`/`cdef class`/`cpdef` symbols at the top level of
   each `pycf/*.py` and `pycf/cfl.pyx`.
2. Map them against the symbols actually imported and called by both the
   in-tree integration tests under `tests/{eryso,ceylf,inten,spin-half}/`
   and two external user scripts identified by the maintainer:
   `~/calculations/f11/erk2yf5/pycf/erk2yf5_example.py` and
   `~/calculations/f11/ysonick/site1pycf/eryso_site1_bobyqa_try_ab-initio.py`.
3. Inspect the assertions in each test to classify them as
   "value-validating" vs "shape/finiteness/no-exception".

### 8.2 Existing assertions are mostly structural, not numerical

Two test directories validate against an external reference and are the
"gold standard":

- `tests/spin-half/test_spin-half.py` — compares pycf's eigenvectors of
  spin-1/2 Zeeman Hamiltonians against `numpy.linalg.eig`.
- `tests/inten/test_inten_*.py` — compares dipole strengths, oscillator
  strengths and Einstein A coefficients against legacy pascal `linuxemp`.

The remaining test files mostly check that calls succeed and shapes are
correct. Examples:

```python
# tests/test_uncovered_modules.py — njsymbols
result = wigner_3j(1/2, 1/2, 1, 1/2, -1/2, 0)
assert np.isfinite(result)            # passes even if value is wrong
assert np.isreal(result)

# tests/test_spinh_comprehensive.py — su2_rz
result = su2_rz(p, m)
assert isinstance(result, np.ndarray) # type only
assert result.dtype == complex
```

The fitting integration tests (`tests/eryso/test_mesh_fit.py`,
`tests/ceylf/test_*`) are *self-consistency* checks — they assert the
fit converges to parameters from prior pycf runs. They will catch
regressions vs the previous pycf version, but cannot detect a bug
introduced *into* that previous baseline.

### 8.3 Specific gaps and proposals

1. **`SpinH` (pycf/spinh.py:476) has no direct unit test.** Used in both
   external user scripts. Proposal: round-trip test that constructs a
   Hamiltonian from known parameters, runs `SpinH` to recover them, and
   asserts agreement to ~1e-10.

2. **`njsymbols` value validation.** Current tests only check
   `np.isfinite(...)`. Two complementary improvements:
   - Reference-table tests (e.g. `wigner_3j(1,1,1,1,-1,0) = 1/√6`,
     `wigner_6j(1,1,1,1,1,1) = 1/6`).
   - Cross-checks against `sympy.physics.wigner` over a parameter sweep
     (~50 cases per symbol; sympy is a test-only dependency). This also
     prepares for a possible later switch to `spherical` or `wigtools`.
   - Symmetry properties (column permutation sign rules for 3j, etc).

3. **`gen_summary()` content is never asserted.** Tests call it and
   `print()` the result without inspecting it. A snapshot-style test
   would catch formatting/numerics regressions cheaply.

4. **`Hamiltonian.add_term` direct test.** Currently exercised only via
   `SpinHamiltonian`. A test that builds a small dense H by `add_term`
   and compares to a hand-summed dense matrix would close this.

5. **One known-eigenvalue assertion per integration test.** Adding (e.g.)
   a Zeeman J=1/2 sub-case that asserts `±½gμ_BB` analytically into the
   fitting tests would convert them from self-consistency to correctness
   tests at minimal cost.

6. **`paramcalc.A_SC`/`A_DC`** vs published tables (Garcia & Faucher /
   Dieke) — would protect against future Ckq/Xi_val refactors.

7. **`set_error_handler` end-to-end test** — already noted in §4 above.

### 9.2 Implementation

Two new test modules were added to close the direct gaps in the table
above:

- **`tests/test_cfl_util_summaries.py`** — 38 tests for the eleven
  untested functions in `cfl_util.py`:
  - `ex_parse_abs`/`ex_parse_diff` are tested with hand-crafted
    duck-typed ExData stand-ins (`SimpleNamespace`) for both
    `sl_index=False` (index-based) and `sl_index=True` (state-label)
    paths, including unsorted-input sorting, `lexsort` ordering of
    diff data by initial-then-final level, the abs/diff partition of
    the `e` array, and missing-label `RuntimeError` paths.
  - `gen_e_summary` / `gen_e_summary_trunc` are tested by feeding small
    synthetic `(w, z, labels)` tuples and asserting the returned string
    contains the expected headings, level numbers, eigenvalues,
    residual values, the `Label key:` line, and that derived `sigma`
    is computed by `sqrt(chi2 / (weighting * ndof))` (correctly
    surfaces `N/A` for `ndof=0` and raises when `weighting` is missing).
  - `gen_sh_summary` is tested with a fake SpinH stand-in for default
    and custom `name=`, with and without `shx`, and the `chi2`/`ndof`
    sigma path with the same N/A/raise behaviour.
  - `gen_fit_summary` is tested for: basic output shape, the
    real-vs-complex covariance-index walk (so a hypothetical
    off-by-one between params would surface as a wrong uncertainty
    value), and the `basinhopping`-method `retval` → `naccept` rename.
  - `print_as_fortran_array` / `print_as_c_array` are tested with
    `capsys` for real-only and complex inputs, including the
    `Re=0 → "0+1.0*I"` normalisation.
  - The three banner helpers are smoke-tested for substring presence.

- **`tests/test_spinh_sym.py`** — 13 tests for the two untested
  symmetrization helpers and the `SpinH.inv_term(sym=True)` path:
  - `su2_rz_lsq_f` and `su2_rotation_lsq_f` are tested with both the
    IAS (2×2 hyperfine) and BgS (3,2,2 g-tensor list) input shapes.
    For an already-symmetric input tensor, the residue at zero phase
    must be < 1e-10 (it is exactly the off-diagonal asymmetry); for
    an asymmetric input tensor, the residue is asserted to be
    finite, real, and strictly positive.
  - `SpinH.inv_term(sym=True, sym_phase=[0,0,0])` is asserted to
    agree to 1e-12 with the no-sym call (the SU(2) identity rotation
    must be a no-op).
  - Wrong-length `sym_phase` raises `ValueError`.
  - The full basinhopping path is exercised under
    `pytest.mark.slow`: a diagonal g-tensor is round-tripped
    through forward + inverse with `sym=True`; the symmetric part of
    the recovered tensor must match the input to ~5e-3 (the
    basinhopping is stochastic, hence the loose tolerance), and the
    callback's stdout output is asserted to confirm that the
    iterations actually ran.
